# Contributing

Start with the development guide and current phase boundary. Discuss changes to result semantics or execution boundaries before implementing them. For a bug report, include the revision, platform, minimal inputs, expected result and observed result. Redact local paths and private data.

Keep patches focused. Include independent expected values for mathematical changes and a keyboard test for interactive controls. Run the relevant quality gates and describe any unavailable verification in the pull request. Review the staged files before committing. Contributions are distributed under the MIT license.
